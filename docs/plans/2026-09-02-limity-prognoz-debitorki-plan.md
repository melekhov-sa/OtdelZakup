# Задача 5791: прогноз дебиторки на дату отгрузки — план реализации

**Спецификация:** `docs/specs/2026-09-02-limity-prognoz-debitorki.md`. Прочитать
до начала: здесь только порядок работ, обоснования решений там.

**Цель.** Индивидуальный лимит партнёра сравнивается с прогнозом долга на дату
отгрузки заказа, а не с сегодняшним долгом. Плюс отчёт, которым этот прогноз
можно проверить по слагаемым.

**Подход.** Один общий модуль считает прогноз и возвращает структуру со всеми
слагаемыми. Его вызывают двое: проверка заказа берёт итог, отчёт рисует
детализацию. Второй реализации расчёта нет нигде.

**Среда.** 1С:Предприятие 8.3.27, конфигурация на УТ. Фреймворка юнит-тестов
в конфигурации нет: модуль `Тестирование` — это сверка эталонных данных для
закрытия месяца, не тесты. Поэтому каждая задача заканчивается **воспроизводимым
сценарием проверки** с конкретными числами, а не запуском тестов.

## Общие требования ко всем задачам

- Правки в типовых объектах помечать комментарием в принятом в конфигурации
  стиле: `//++ Фамилия (фрагмент ДОБАВЛЕН) ДД.ММ.ГГГГ ЧЧ:ММ:СС #5791`
  и закрывающим `//++ Фамилия ДД.ММ.ГГГГ ЧЧ:ММ:СС`. Заменённые строки
  оставлять закомментированными через `//==`, как сделано в #5753.
- Все суммы — в валюте управленческого учёта. Ресурсы `*ВВалютеОтчета`
  в регистре долга не использовать без отдельного решения.
- Партнёров **без** индивидуального лимита новый механизм не касается вообще:
  для них по-прежнему работает договорный контроль.
- Ничего не удалять из старого расчёта до задачи 6. До неё новый код лежит
  рядом и не влияет на проведение заказов.
- После каждой задачи — выгрузка изменённых объектов в XML и коммит.

## Задача 4. Возврат денег по этим заказам

Самая содержательная часть. График оплаты из соглашения разносит сумму
позиции по этапам, и в вычет идут только те доли, чья дата не позже прогноза.

**Файлы:** изменить `CommonModules/ПрогнозДебиторскойЗадолженности/Ext/Module.bsl`

**Берёт:** таблицу из `ОтгрузкиДоДаты` (задача 3)
**Отдаёт наружу:** `ВозвратПоОтгрузкам(ТаблицаОтгрузок, ДатаПрогноза) → ТаблицаЗначений`
с колонками `Заказ`, `Номенклатура`, `ДатаОтгрузки`, `ВариантОплаты`, `Сдвиг`,
`ПроцентПлатежа`, `ДатаОплаты`, `Сумма`, `ВошлоВВычет`, `Причина`

Колонки `ВошлоВВычет` и `Причина` нужны отчёту: он должен показывать не только
что зачлось, но и что не зачлось и почему.

- [ ] **Шаг 1. Написать разбор графика**

```bsl
// Разносит суммы отгружаемых позиций по этапам графика оплаты из соглашения.
//
// Этап даёт долю ПроцентПлатежа к дате «дата отгрузки позиции + Сдвиг».
// В вычет идёт только доля с датой не позже прогноза: деньги, приходящие
// после этой даты, на неё ещё не пришли.
//
// Авансовые этапы уменьшают долг независимо от даты прогноза: они приходят
// до отгрузки, а значит и до прогнозируемого момента.
//
Функция ВозвратПоОтгрузкам(ТаблицаОтгрузок, ДатаПрогноза) Экспорт

	Результат = Новый ТаблицаЗначений;
	Для Каждого ИмяКолонки Из СтрРазделить(
		"Заказ,Номенклатура,ДатаОтгрузки,ВариантОплаты,Сдвиг,ПроцентПлатежа,ДатаОплаты,Сумма,ВошлоВВычет,Причина", ",") Цикл
		Результат.Колонки.Добавить(ИмяКолонки);
	КонецЦикла;

	КэшГрафиков = Новый Соответствие;

	Для Каждого Отгрузка Из ТаблицаОтгрузок Цикл

		Этапы = ЭтапыГрафика(Отгрузка.Соглашение, КэшГрафиков);

		Если Этапы.Количество() = 0 Тогда
			Строка = Результат.Добавить();
			Строка.Заказ = Отгрузка.Заказ;
			Строка.Номенклатура = Отгрузка.Номенклатура;
			Строка.ДатаОтгрузки = Отгрузка.ДатаОтгрузки;
			Строка.Сумма = 0;
			Строка.ВошлоВВычет = Ложь;
			Строка.Причина = "В соглашении не задан график оплаты";
			Продолжить;
		КонецЕсли;

		Для Каждого Этап Из Этапы Цикл

			Строка = Результат.Добавить();
			Строка.Заказ = Отгрузка.Заказ;
			Строка.Номенклатура = Отгрузка.Номенклатура;
			Строка.ДатаОтгрузки = Отгрузка.ДатаОтгрузки;

				КонецЕсли;
			КонецЕсли;

		КонецЦикла;
	КонецЦикла;

	Возврат Результат;
```

Состав структуры — это и контракт для отчёта:

```
ДолгНаСегодня          Число
Поступления            Число      ПоступленияДетали      ТаблицаЗначений
Отгрузки               Число      ОтгрузкиДетали         ТаблицаЗначений
Возврат                Число      ВозвратДетали          ТаблицаЗначений
ПрогнозБезЗаказа       Число
СуммаЗаказа            Число
ПредоплатаПолучена     Число
ПрогнозСЗаказом        Число
Лимит                  Число
Свободно               Число
```

- [ ] **Шаг 1. Написать сборку**

```bsl
// Прогноз долга партнёра на указанную дату.
//
// Возвращает структуру со всеми слагаемыми, а не одно число: тем же
// результатом пользуется отчёт, и детализация должна приходить из того же
// расчёта, что и итог. Отдельная реализация в отчёте сверяла бы одну копию
// формулы с другой.
//
Функция ПрогнозНаДату(Партнер, ДатаПрогноза, Заказ = Неопределено) Экспорт

	Результат = Новый Структура(
		"ДолгНаСегодня, Поступления, ПоступленияДетали, Отгрузки, ОтгрузкиДетали,
		|Возврат, ВозвратДетали, ПрогнозБезЗаказа, СуммаЗаказа, ПредоплатаПолучена,
		|ПрогнозСЗаказом, Лимит, Свободно");

	Результат.ДолгНаСегодня = ДолгНаСегодня(Партнер);

	Результат.ПоступленияДетали = ПоступленияДоДаты(Партнер, ДатаПрогноза);
	Результат.Поступления = Результат.ПоступленияДетали.Итог("Сумма");

	Результат.ОтгрузкиДетали = ОтгрузкиДоДаты(Партнер, ДатаПрогноза, Заказ);
	Результат.Отгрузки = Результат.ОтгрузкиДетали.Итог("Сумма");

	Результат.ВозвратДетали = ВозвратПоОтгрузкам(Результат.ОтгрузкиДетали, ДатаПрогноза);
	Результат.Возврат = 0;
	Для Каждого Стр Из Результат.ВозвратДетали Цикл
		Если Стр.ВошлоВВычет Тогда
			Результат.Возврат = Результат.Возврат + Стр.Сумма;
		КонецЕсли;
	КонецЦикла;

	Результат.ПрогнозБезЗаказа = Результат.ДолгНаСегодня
		- Результат.Поступления + Результат.Отгрузки - Результат.Возврат;

	Результат.СуммаЗаказа = 0;
	Результат.ПредоплатаПолучена = 0;
	Если ЗначениеЗаполнено(Заказ) Тогда
		Результат.СуммаЗаказа = Заказ.СуммаДокумента;
		Результат.ПредоплатаПолучена = ПолученнаяПредоплата(Заказ);
	КонецЕсли;

	Результат.ПрогнозСЗаказом = Результат.ПрогнозБезЗаказа
		+ Результат.СуммаЗаказа - Результат.ПредоплатаПолучена;

	Результат.Лимит = ЛимитПартнера(Партнер);
	Результат.Свободно = Результат.Лимит - Результат.ПрогнозСЗаказом;

	Возврат Результат;

КонецФункции
```

```
  − Возврат по ним до 15.12                                0

                  позже D, в вычет не идёт
  ──────────────────────────────────────────────────────────
  Прогноз без нового заказа                          350 000
  + Заказ №90, ставим к выполнению                  +300 000
  − Предоплата получена                              −90 000
  ──────────────────────────────────────────────────────────
  Прогноз на дату отгрузки                           560 000
  Свободно до лимита                                  40 000
```

Строки, **не вошедшие** в вычет, выводить наравне с вошедшими, с текстом
из колонки `Причина`. Их отсутствие и есть самая частая причина расхождений
при разборе.

- [ ] **Шаг 3. Добавить команду в форму заказа**

Кнопка «Прогноз дебиторки» в форме `ЗаказКлиента`, открывает отчёт
с заполненными параметрами: партнёр из заказа, дата из `ДатаОтгрузкиДляЛимита()`,
заказ — текущий.

- [ ] **Шаг 4. Сверить отчёт с проверкой**

Это ключевая проверка всей задачи.

Взять заказ, который проверка **отклонила**. Открыть по нему отчёт. Итог
`Прогноз на дату отгрузки` должен совпасть с числом, при котором проверка
приняла решение, а `Свободно` быть отрицательным.

Повторить на заказе, который прошёл: `Свободно` положительное.

Расхождение означает, что отчёт считает по-своему — искать причину, а не
править отображение.

## Задача 8. Отчёт, остальные два режима

**Файлы:** изменить `Reports/ПрогнозДебиторскойЗадолженности`

- [ ] **Шаг 1. Режим «по партнёру на дату»**

Параметры: партнёр и произвольная дата, заказ не задаётся. Отчёт показывает
те же слагаемые, но без блока нового заказа: `Прогноз без нового заказа`
становится итогом.

Проверка: задать дату, на которую попадает кредитный этап заказа из задачи 4,
и убедиться, что строка перешла из «не вошло» в «вошло» с той же суммой.

- [ ] **Шаг 2. Режим «список партнёров с лимитами»**

Строка на партнёра: лимит, прогноз на сегодня, свободно. Без детализации,
с возможностью провалиться в режим «по партнёру».

```bsl
Запрос.Текст =
"ВЫБРАТЬ
|	ЛимитыПоПартнерам.Партнер КАК Партнер,
|	ЛимитыПоПартнерам.Лимит КАК Лимит
|ИЗ
|	РегистрСведений.ЛимитыПоПартнерам КАК ЛимитыПоПартнерам
|ГДЕ
|	ЛимитыПоПартнерам.Лимит > 0";
```

Дальше по каждому партнёру вызвать `ПрогнозНаДату(Партнер, ТекущаяДатаСеанса())`.

Если партнёров с лимитами больше сотни, замерить время построения. Расчёт
на партнёра включает три запроса; при неприемлемом времени вынести этот режим
в фоновое задание, но **не** заводить отдельный упрощённый расчёт.

- [ ] **Шаг 3. Проверить сходимость режимов**

Для одного партнёра открыть режим «список» и режим «по партнёру на сегодня».
Числа в колонке «Свободно» должны совпасть.

```

```

## Что проверить до начала работы

Пять пунктов из спецификации, помеченных как непроверенные. Каждый может
изменить реализацию, поэтому выяснять их надо до кода, а не в процессе:

1. Чем и как часто заполняется `ДебиторскаяЗадолженность_История`. Свежесть
   этих данных — потолок точности всего механизма.
2. Значения перечисления `ВариантОплаты` в `ГрафикиОплаты.Этапы` — какие
   означают оплату до отгрузки (задача 4, шаг 3).
3. Как определяется «позиция ещё не отгружена» (задача 3, шаг 2).
4. Ресурс регистра расчётов, по которому считать полученную предоплату
   (задача 5, шаг 2).
5. Не ломает ли изменение `ЛимитИсчерпан` портфельный лимит по сегменту
   отсрочки (#5754), который вызывается следом.

И отдельно — расхождение с постановкой, описанное в спецификации: сейчас
в индивидуальном лимите заказы к выполнению **не учитываются**. Подтвердить
на данных до начала работы.
