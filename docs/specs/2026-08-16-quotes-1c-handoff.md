# Задание для 1С: сравнение коммерческих предложений поставщиков

Серверная часть **готова и закоммичена** (`89715bd`). Здесь описано, что осталось
сделать в 1С. Исполнитель начинает с нуля — весь нужный контекст ниже.

Это третье задание по проекту. Первое — «колонка Номенклатура МЗ, кандидаты
подбора и перенос в заказ клиента». Второе было спецификацией серверной части
и уже реализовано, повторять его не нужно.

---

## 1. Что происходит

**Python-сервис «OtdelZakup»** — FastAPI, `Srv-sq-b1`, `Z:\ProjectZ`, служба NSSM
`OtdelZakup`, порт 8000. Распознаёт метизы и сопоставляет их с внутренним
каталогом (~220 тыс. позиций).

**Пользователь — МЗ, менеджер по закупкам.** Она знает номенклатуру идеально.

Сценарий, который надо закрыть:

1. У МЗ есть выверенный список позиций — каждая уже ссылка на справочник
   номенклатуры (первое задание это обеспечивает).
2. Поставщики присылают КП: разные файлы, разные наименования одних и тех же
   метизов, **разные единицы измерения**.
3. МЗ загружает все КП и получает сводную таблицу «позиция × поставщик»
   с ценами, приведёнными к одной единице.

Разбор наименований, сопоставление и пересчёт цен делает сервис.
**Со стороны 1С нужны только вызовы и экран.**

## 3. Контракт API

Все три endpoint принимают и отдают JSON. Ошибки — `{"error": "текст"}`
с кодом 400 или 404.

### 3.1 Создать сравнение

```
POST /api/v1/comparison
```

```json
{
  "external_ref": "b8f4c1a2-...",
  "title": "Заявка №123",
  "positions": [
    {"uid_1c": "0649541b-ae24-...", "qty": 100, "unit": "шт", "weight_kg": 0.085}
  ]
}
```

Ответ:

```json
{"comparison_id": 17, "positions_total": 30, "not_found": ["uid-1", "uid-2"]}
```

- `external_ref` — идентификатор со стороны 1С, обычно УИД заявки.
  **Повторная отправка с тем же `external_ref` заменяет позиции**, а не плодит
  дубли, и возвращает тот же `comparison_id`. Пересоставили список — просто
  отправьте заново.
- `uid_1c` — УИД номенклатуры. Позиции, которых нет в каталоге сервиса,
  возвращаются в `not_found`; запрос при этом успешен.
- `unit` и `weight_kg` — **берутся из карточки номенклатуры 1С**. От них зависит
  весь пересчёт цен, см. раздел 4. Вес в килограммах на одну единицу.
  Если вес не заполнен — не отправляйте поле или шлите `null`, но **не ноль
  и не выдуманное значение**.

Полученный `comparison_id` сохранить в заявке — он нужен для двух других вызовов.

### 3.2 Загрузить коммерческое предложение

```
POST /api/v1/comparison/{comparison_id}/quotes
```

```json
{
  "supplier": "ООО Ромашка",
  "filename": "price.xlsx",
  "file_base64": "UEsDBBQABgAIAAAAIQ...",
  "hint": "table"
}
```

Ответ:

```json
{"quote_id": 42, "lines_total": 150, "matched": 28, "matched_auto": 20,
 "suggested": 8, "unmatched": 4, "filtered": 118}
```

- Форматы: `.xlsx`, `.csv`, а также `.pdf` и изображения — сканы уходят
  в Google Document AI на стороне сервиса.
- `hint` нужен только для PDF и картинок: `"table"` (по умолчанию),
  `"structured_text"`, `"free_text"`.
- Колонки в Excel сервис определяет сам — мастера сопоставления в API нет.
- Строки сразу сопоставляются с позициями, отдельного вызова не требуется.
- `filtered` — отброшенные шапки, итоги и реквизиты. Показывать не нужно,
  но число полезно как признак «файл распознан странно».
- **Base64 без переносов строк.** `Base64Строка()` в 1С вставляет перенос
  каждые 76 символов — их надо убрать, как это уже сделано в существующем
  методе `РазобратьФайл` общего модуля `РазборЗаявокAPI`.

Каждый файл — отдельный вызов. Один поставщик может прислать несколько файлов,
каждый станет отдельным КП; поставщик заводится по имени при первом упоминании.

### 3.3 Забрать сводную таблицу

```
GET /api/v1/comparison/{comparison_id}
```

```json
{
  "comparison_id": 17,
  "suppliers": ["ООО Ромашка", "ООО Василёк"],
  "rows": [
    {
      "position_no": 1,
      "uid_1c": "0649541b-...",
      "name": "Болт М12х80 ГОСТ 7798-70",
      "qty": 100,
      "unit": "шт",
      "cells": {
        "ООО Ромашка": {
          "price": 14.20, "currency": "RUB", "unit": "шт",
          "price_normalized": 14.20, "basis": "same_unit",
          "suspicious": false, "score": 0.93
        },
        "ООО Василёк": {
          "price": 167.00, "currency": "RUB", "unit": "кг",
          "price_normalized": 14.195, "basis": "weight",
          "suspicious": false, "score": 0.88
        }
      }
    }
  ],
  "unmatched": {
    "ООО Ромашка": [{"row_no": 88, "raw_text": "Хомут 20-32", "price": 12.0, "unit": "шт"}]
  },
  "filtered_count": {"ООО Ромашка": 118}
}
```

- В `rows` — **строка на каждую позицию сравнения**, включая те, которые
  не предложил никто. Нет ячейки для поставщика — он эту позицию не закрывает.
- `unmatched` — строки КП, которые сервис не смог отнести ни к одной позиции.
  Показывать обязательно: поставщик что-то предложил, а мы это не опознали.
- `score` — степень совпадения строки КП с позицией, 0…1.

## 4. Пересчёт цен — что показывать МЗ

Это самая ответственная часть экрана. Поставщики дают цены в разных единицах,
и наивное сравнение чисел опаснее пустой ячейки.

**Правило: `price` — факт от поставщика, он показывается всегда.**
`price_normalized` — расчёт, и он всегда идёт вместе с `basis`.

| `basis` | Что произошло | Как показывать |
|---|---|---|
| `same_unit` | Единицы совпали | Просто цена |
| `pack` | В тексте строки КП нашлась фасовка («уп. 100 шт») | «≈ 14.20 за шт (по упаковке)» |
| `weight` | Цена за кг пересчитана по весу номенклатуры | «≈ 14.20 за шт (по весу)» |
| `none` | Пересчёт невозможен | «не сравнимо», цена за исходную единицу |

`price_normalized` при `basis = "none"` приходит `null`. **Не подставляйте вместо
него исходную цену, ноль или единицу** — пустое значение честнее неверного.
Именно ради этого правила всё и делалось.

Фасовка приоритетнее веса: она из самого предложения поставщика, а вес — из нашей
карточки, и заказчик прямо предупредил, что он неидеален.

**`suspicious: true`** — приведённая цена отличается от остальных поставщиков
по этой позиции на порядок. Ячейку **не прятать**: подсветить и дать подсказку
вроде «проверьте вес в номенклатуре». Чаще всего это и есть ошибка веса
в справочнике, и так она найдётся.

Выбор лучшей цены МЗ делает по приведённой колонке, но должна видеть,
что за ней стоит.

## 5. Что сделать в 1С

### 5.1 Общий модуль `РазборЗаявокAPI`

Модуль **клиентский**, флаг «Сервер» не ставить — служба 1С блокирует исходящие
HTTP-соединения. Добавить три метода по образцу существующих:

- `СоздатьСравнение(Заявка, МассивПозиций)` → `{Успех, Ошибка, ИдСравнения, НеНайдены}`
- `ЗагрузитьКП(ИдСравнения, ИмяПоставщика, ПутьКФайлу, Режим = "table")` → `{Успех, Ошибка, Статистика}`
- `ПолучитьСравнение(ИдСравнения)` → `{Успех, Ошибка, Поставщики, Строки, НеОпознанные}`

Позиции для `СоздатьСравнение` собирать из табличной части `РазборЗаявкиОтИИ`
справочника `ЗаявкиОтделаПродажПоЗакупкам`: брать `НоменклатураМЗ` (а при её
отсутствии — не брать позицию вовсе), её УИД, количество, единицу и **вес
из карточки номенклатуры**.

> **Внимание на таймаут.** В `ПолучитьНастройкиПодключения()` зашит таймаут
> HTTP-соединения 60 секунд. Разбор PDF-прайса на сотни строк в него может
> не уложиться, и 1С оборвёт соединение раньше, чем сервис ответит.
> Для вызова `ЗагрузитьКП` таймаут поднять до 300 секунд. Остальные вызовы
> быстрые, их не трогать.

> Там же зашит адрес `127.0.0.1:8000`. Если обработка запускается не на самой
> машине сервиса — заменить на `Srv-sq-b1`.

### 5.2 Экран сравнения

Новая форма (или новая страница существующей обработки) с тремя частями.

**Загрузка.** Поле выбора файла, поле имени поставщика, кнопка «Загрузить КП».
После загрузки — строка статистики: сколько строк, сколько сопоставлено,
сколько не опознано. Список уже загруженных КП с возможностью загрузить ещё.

**Сводная таблица.** Колонки: номер, наименование позиции, требуемое количество,
затем по колонке на каждого поставщика из `suppliers`. В ячейке — цена, единица,
приведённая цена с основанием (раздел 4). Лучшую приведённую цену в строке
выделять. Ячейки с `suspicious` подсвечивать отдельно.

**Не опознано.** Отдельный список из `unmatched` по поставщикам — что предложили,
но не легло ни на одну позицию. МЗ должна это видеть: там может оказаться нужная
позиция под непривычным названием.

### 5.3 Когда обновлять таблицу

`GET` вызывать после каждой загрузки КП и по кнопке «Обновить». Таблица целиком
пересобирается на сервере, инкрементальных обновлений нет.

## 6. Критерии приёмки

1. МЗ создаёт сравнение из заявки; позиции без `НоменклатураМЗ` не отправляются.
2. Позиции, которых нет в каталоге сервиса, показаны отдельным сообщением
   из `not_found`, а не потеряны молча.
3. Загружаются несколько КП от разных поставщиков, в том числе `.xlsx` и `.pdf`.
4. Base64 уходит без переносов строк; файл на несколько сотен строк
   не обрывается по таймауту.
5. В таблице есть строка на каждую позицию, включая те, что не предложил никто.
6. Цена за килограмм показана и как есть, и приведённой к штуке с пометкой «по весу».
7. При незаполненном весе ячейка помечена «не сравнимо», а не показывает
   цену за килограмм как сравнимую.
8. Строка КП с фасовкой в тексте пересчитана с пометкой «по упаковке».
9. Ячейки с `suspicious` подсвечены и остаются видимыми.
10. Строки КП из `unmatched` показаны отдельным списком.
11. Повторное создание сравнения с тем же `external_ref` не плодит дубли.

## 8. Известные ограничения

- **Вес номенклатуры неидеален** — заказчик предупредил. Поэтому пересчёт по весу
  всегда помечен как расчётный, а выбросы флагуются. Не «улучшайте» это,
  скрывая пометки.
- **Выбор победителя сервис не делает.** Он отдаёт цифры, решение за МЗ.
  Что делать с выбранным поставщиком дальше — отдельная задача, в это ТЗ
  не входит.
- **Внешние ключи SQLite** включаются на сервисе точечно, не глобально.
  На 1С не влияет, но при удалении сравнений через API возможны остатки —
  массово удалять сравнения пока не нужно.
